# Monday 9 Nov 2026 — one product for Shopee, TikTok Shop, and the ISV demo

Owner, 6 Nov 2026: sync the ISV application demo (mock data) and TikTok Shop with the Shopee
product. No more hand-maintained, separate versions. This plan also takes the open P94 groups,
the Ops/Demo bug-log extension, and the P95 parity estimate, which is no longer "not scheduled".

Monday locks the seams and the mock contract. It does not ship TikTok parity or P94.

## Decision

There is one screen set: the Shopee shell in `SHOPEE_DESTINATIONS`
(`apps/demo/src/lib/app-navigation.ts`) — Tổng quan, Phân tích, Sản phẩm, Quyết định, Từ khóa,
Quảng cáo, Đơn hàng, Luồng, plus the builder, compare, plans, and KOL screens behind them.

The marketplace changes the data, not the screens.

| Who | Data | Screens |
|---|---|---|
| Shopee shop (ORY and later sellers) | Live Shopee reads, as now | Shopee shell |
| TikTok shop (Fujiwa and later sellers) | TikTok adapter, same read models | Shopee shell |
| ISV trial on demo.app-juli.com | Mock shop that speaks those same read models, labelled as sample data | Shopee shell |
| Anonymous visitor | The same mock shop, still labelled | Shopee shell |

`APP_DESTINATIONS` (Trang chủ / Quyết định / Phân tích / locked Juli) stops being a second product.
`destinationsFor` no longer switches shell by platform.

P94 is the only version model, built once on this shell: several options of a card are approved
as a group (Nhóm A, then B, C), evaluated together, and measured as one change set. A hand-edited
sample of "versions" in the old demo is not a version model.

## What is separate today

- TikTok shops get `APP_DESTINATIONS`. `/v1/demo/shopee/*` answers them `409 not_a_shopee_shop`
  (`apps/demo/src/lib/shopee-analytics/platform.ts`). That gate is the split this plan removes.
- The ISV trial still has two older stories. D42 sample mode is the bundled shop "Cửa hàng Mẫu
  Hoa Mai" (`apps/demo/src/lib/phan-tich/sample-data.ts`, `lib/quyet-dinh/sample-data.ts`,
  `lib/reviewer/sample-store.ts`) with browser-side simulation and no shop API. D73/D77 pin the
  reviewer to Fujiwa (masked, read-only) and the TikTok sandbox (real listing writes) on the
  legacy screens. Shopee rejected mock-only interfaces (D73). The live TikTok connection on the
  trial account stays, as proof of the integration. The screens around it become this shell.
- P94 is a contract only (`contracts/p94-multi-approve.md`). No group model, route, or migration.
- P95 is an estimate only (`contracts/p95-tiktok-parity-estimate.md`), marked not scheduled. The
  phases below are that estimate, now on this plan.
- The Ops QA extension was ordered 5 Nov and never specified. There is no second extension, no
  bug-log fields, and no backend route. It is not the Juli Connector.

## Bug log — fields and sync

A browser extension, separate from the Juli Connector, used on Ops and on Demo. It posts to the
backend. It does not write Seller Centre and it does not read shop data.

The report, all of it:

| Field | Required | Notes |
|---|---|---|
| `surface` | yes | `ops` or `demo` |
| `route` | yes | path the person was on |
| `shop_id` | no | the acting shop, when there is one |
| `platform` | yes | `shopee`, `tiktok`, or `sample` |
| `what_happened` | yes | short text |
| `expected` | yes | short text |
| `field_name` | no | the input, when the bug is a field |
| `field_value` | no | what was typed; never a token, password, or buyer PII |

`POST /v1/ops/bug-reports` accepts this from a signed-in Ops or staff session. The extension
stores nothing locally after a successful post. Ops lists the reports; it does not become a
second issue tracker. Screenshot and a GitHub issue are out of this cut.
