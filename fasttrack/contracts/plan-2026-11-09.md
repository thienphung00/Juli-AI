# Monday 9 Nov 2026 — one product for Shopee, TikTok Shop, and the ISV demo

Owner, 6 Nov 2026. The ISV demo (mock data) and TikTok Shop use the same screens as Shopee.
P94 (groups) and P95 (TikTok parity) are in this plan, not beside it. P95 is no longer
"not scheduled".

Shops are dynamic. Nothing in the product is compiled for ORY, Fujiwa, or any other shop id.
The two platforms differ because their data arrives differently and because their Seller Centre
fields differ. A shared gate covers the fields both have. Each platform has its own gate for
the rest. The Juli Connector fills Seller Centre fields for both platforms, and both a developer
and a seller can use it on a shop they are allowed to open.

Monday locks these rules. It does not ship the TikTok adapter or P94.

## One shell, two data paths

The shell is `SHOPEE_DESTINATIONS` (`apps/demo/src/lib/app-navigation.ts`): Tổng quan, Phân tích,
Sản phẩm, Quyết định, Từ khóa, Quảng cáo, Đơn hàng, Luồng, plus builder, compare, plans, and KOL.
`APP_DESTINATIONS` (Trang chủ / Quyết định / Phân tích) stops being a second product.
`destinationsFor` no longer switches shell by platform.

| Platform | How data arrives | Who |
|---|---|---|
| Shopee | Imported files (orders, income, costs, planned changes) plus the Juli Connector reading Seller Centre | Every shop with `platform = shopee` that has uploaded files or paired a connector |
| TikTok Shop | Real partner endpoints (orders, products, inventory, returns, settlements, promotions, analytics), polled and webhooked per that shop's own credential | Every shop with `platform = tiktok` that has connected |
| Sample | The same read models, filled with labelled mock rows | ISV trial and anonymous visitor |

A shop id never selects a code path. `PILOT_SHOP_IDS` in `apps/connector/src/config.ts` is one
compiled-in id today, and fill-in, market search, and the scheduler all consult it. That list
goes away. A paired connector acts for the shop on its ingest token. Adding a shop is a row and
a pairing, not a release.

The reviewer pins (`REVIEWER_SHOP_IDS`) stay an access rule: which shops that account may open,
and that Fujiwa is masked and read-only while the TikTok sandbox may write listings (D73, D77).
They are not a product fork and they are not the only TikTok shop the screens know.

## Field gates

TikTok and Shopee do not have the same features. The screen asks two questions before it shows
or writes a field.

**Shared gate.** The field means the same thing on both platforms. One read model, one card
kind, one builder control. The platform only supplies the loader and the Seller Centre writer.
Shared, until a field is proved otherwise: title, price, cover image, description, a product
discount, orders, GMV, units, fees that have already been paid, contribution, the version row,
and the P94 group.

**Shopee gate.** Shown and written only when `platform = shopee`. File-import income and VAT,
Shopee voucher shape (min spend / value), combo, mua kèm, quà tặng, flash-sale slots, variation
sets, KOL × product from the affiliate report, keyword volumes from the export, ads read from
Seller Centre through the Connector. Empty on a TikTok shop, with the reason, not a fake zero.

**TikTok gate.** Shown and written only when `platform = tiktok`. Partner-API promotions and
listing edits, read-back after a write, LIVE / video / product-card flows, settlement and
statement fees in place of the Shopee income file, listing diagnosis. GMV Max and TikTok ads
stay behind this gate and stay empty until the Business API scope exists (P95 P5). Keyword
volume has no TikTok source; the panel says so.

A sample shop uses the shared gate. A platform-only panel on the ISV trial shows the mock when
the trial is demonstrating that platform, labelled "dữ liệu mẫu", and an honest empty state
when the sandbox cannot fill it. Mock rows use the response shape of that gate. They are not a
second screen and not hand-written numbers the API does not return.

The old `409 not_a_shopee_shop` split (`apps/demo/src/lib/shopee-analytics/platform.ts` and
`_shopee` on the P90–P92 routes) becomes these three gates. A TikTok shop no longer falls off
the shell.

## P94 — groups, once, on this shell

From `contracts/p94-multi-approve.md`. Built once. The field gates decide which option types a
platform can put in a group. There is no Shopee copy and no TikTok copy of the group model.

- Every card, engine or manual, can approve more than one version. Example: voucher 15k/200k
  and 20k/250k together.
- Versions approved together are a group, Nhóm A, with one period (start, N days, minimum 3).
  Three vouchers for 3 days is one group. Nhóm B, C, … on the same card run after A ends, or
  from a chosen date.
- Inside a group the options are one bundle on the same orders. Each buyer gets the best option
  their basket qualifies for. Combos, add-ons, gifts, flash-sale slots, sets, and affiliate
  targets coexist with shared demand and are not double counted. The group shows combined ΔGMV,
  Δ orders, Δ profit, margin, cost, and each option's share. Floor and spend-cap warnings apply
  to the combination and do not block. A group is one change set for measurement (P91 D-7).
- One live value per exclusive field: title, price, cover, description first line, a discount
  on the same variation, one campaign's budget or ROAS. A second option of that field goes to
  the next group, is measured on its own, and the better one is suggested to keep. An exclusive
  field the platform does not have is refused by that platform's gate, not stored as a dead row.
- Draft plans take groups as steps. Confirmation runs them on the schedule. Connector fill-in
  prepares the exclusive-field value of the group whose turn it is, on that shop's Seller Centre.
- Codes: a group is `JC-…-G<A|B…>`, versions keep `-V<n>`. Excel lists group, versions, period.

## Juli Connector — Dev and Seller, both Seller Centres

The Connector is the writer and the Shopee reader. It is not a second product and it is not
tied to one operator.

- A seller pairs it to their own shop and fills that shop's Seller Centre.
- A developer pairs it to a shop they may open (the TikTok sandbox, a Shopee test shop) and
  fills that shop's Seller Centre. The pairing is the same code the seller uses.
- Shopee reads stay files + Connector. TikTok reads stay the partner API. Fill-in on TikTok
  writes the TikTok Seller Centre fields the TikTok gate allows; fill-in on Shopee writes the
  Shopee fields the Shopee gate allows. Shared fields use one payload and the platform's page
  matcher (`banhang.shopee.vn` or the TikTok seller host).
- The server returns the fill for the token's shop only, as it does now for Shopee listings.
  `CONNECTOR_FILL_LISTING` remains the kill switch. The shop allowlist is "this token's shop",
  not `PILOT_SHOP_IDS`.
- The person saves. The Connector prepares the group's current exclusive field (P94) and does
  not submit it.
- The bug-log extension below is a different extension. It does not fill fields.
