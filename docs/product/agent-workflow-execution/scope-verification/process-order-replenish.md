## Ranked top-8 discovered-in-implementation gaps

1. **`workflow_runs.product_id` is NOT NULL**, uniqueness `(shop, product)` (`models.py:576,620-627`) — the dispatch-window subject cannot exist. All of §4 sits behind it.
2. **Nothing schedules anything.** Approval is the sole run creator; card refresh is manual; no per-shop window or timezone. "Two scheduled runs a day" has no substrate, not even a place to configure the windows.
3. **`rts_sla` exists in no code and no capture.** The proxy is a global 48 h constant off `payment_time`. PO-FR-2's sort key, FR-8's push offset and NFR-4's measure all depend on a field nobody has yet observed from TikTok.
4. **The sandbox merchant cannot read orders** (`capabilities.py:125-166`, `factories.py:89-99`) — PO-FR-5's re-verify and the §7 gate walk are structurally impossible until the allowlist and a sandbox order exist.
5. **`committed_quantity` neither stored nor observed non-zero, multi-warehouse unrepresentable** — RI-FR-5, RI-NFR-1 and RI-NFR-3 all rest on it.
6. **No TikTok replenishment-recommendation endpoint** — RI-FR-2's headline cannot be built as written.
7. **The clean predicate has no facts to read** — lossy status mapping, no cancellation transformer, `workflow_webhook_signals` shop-scoped with an unused reader.
8. **The confirmation UI is scalar-only** (`review.ts:15-23`); the demo renders the batch as the string `"Hàng đợi T5 — 6 đơn"`. Backend shape is fine; the surface is not.
