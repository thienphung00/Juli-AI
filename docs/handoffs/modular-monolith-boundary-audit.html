5. Shared code vs business modules

Belongs in shared (today: core / database / models / repos)

  • Config & runtime helpers — core/config
  • JWT / AuthZ dependencies — core/security (partially leaking TikTok OAuth orchestration)
  • Engine/session/Alembic — database/
  • ORM Base — orm_base.py
  • Cross-cutting Redis rate limiter lives under integrations (OK if treated as infra adapter)

Business logic leaking into “shared”

  • core/security/tiktok_oauth.py orchestrates shop provisioning + TikTok auth (domain, not pure auth primitive)
  • models/models.py (~813 LOC) mixes identity, commerce, ETL, ML graph, execution, alerts
  • repositories/repos.py (~1203 LOC) is a monolith data-access bag — no per-module ownership
  • No dedicated shared/ package name; “shared” is implicit via these folders

10. Assessment

5.5

As a modular monolith: clear folder intent and planning SoT (MODULES.md), but soft runtime boundaries. Shared god-models/repos, deep cross-imports, cycles, and non-enforced contracts keep this in the mid band — better than a classic ball-of-mud, far from a 9/10 “modules with hard shells.”

Top 5 changes to reach ~9/10 (no microservices)

  1. Introduce import-linter (or AST CI) with allowed dependency matrix; fail PRs on forbidden edges.
  2. Split god files models/models.py (~813 LOC) and repositories/repos.py (~1203 LOC) into per-domain packages with clear ownership.
  3. Enforce package-root imports only: consumers use services.X / integrations.tiktok public __init__; ban deep submodule imports.
  4. Break cycles (execution↔operations, security↔tiktok services, action_cards/execution↔workers.tasks) via ports/adapters.
  5. Make API routes thin adapters: one owning service per router; no direct integrations/tiktok or models imports in routes.

Scoring rationale

  • + Documented modules & MODULE.md culture
  • + Thin Celery task wrappers
  • + Nightly cycle/drift audits exist
  • − No forbidden-import CI on PRs
  • − Shared models/repos megafiles
  • − API/integration deep coupling
  • − Bidirectional service cycles
